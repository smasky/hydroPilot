## Changes

### `discovery.py` — soils.sol parser + mapping (+62 lines)

**`_parse_soils_sol(file_path)`** — parses soils.sol into `{profile_index: {name, nly, hyd_grp}}`.

- Skips 2 header lines (title + column names)
- Profile rows identified by first token being non-numeric (name like `soil_01` or `SONGSAN`)
- Layer rows begin with numeric depth values and are skipped
- Returns `(n_soils, soil_profiles)` — 1-based indexing
- Gracefully returns `(0, {})` when file is missing

**`build_soil_profile_map(hru_meta, soil_profiles)`** — maps each HRU's soil value to a soils.sol profile index.

- Two-pass matching:
  1. **Exact match**: `hru_meta[soil]` directly found in profile names
  2. **Hydro-suffix fallback**: regex `^(.+)-[a-z]+\d+$` strips suffix (e.g., `soil_01-h1` → `soil_01`, `soil_01-h99` → `soil_01`), retries match
- Returns `{hru_id: profile_index}` — omits HRUs whose soil value can't be matched
- Empty map when soil_profiles is empty

**`discover_swatplus_project()`** updated to return `n_soils`, `soil_profiles`, `soil_profile_map`.

## Edge Cases Documented

| Case | Behavior |
|------|----------|
| Hydro variant exists as separate profile | Exact match wins → maps to variant profile (soil_01-h1 → 13, not 1) |
| Hydro variant NOT in soils.sol | Suffix stripped → maps to base profile (soil_01-h99 → 1) |
| Unknown soil name, no match | HRU omitted from map |
| No soils.sol in project | n_soils=0, empty map |
| Non-hydro suffix (e.g., PadHOEGOG) | Exact match against profile name (Osu_1hru style) |
| Multiple hydro variants of same base | Each gets own profile index (soil_01, soil_01-h1 are separate) |

## Risk

- Hydro-suffix regex `^(.+)-[a-z]+\d+$` assumes lowercase letter + digit after `-`. Osu_1hru names like `PadHOEGOG` don't match this pattern (no digit after `-`) → exact match only. This is correct for those projects.
- The mapping is built at discovery time and doesn't update if soils.sol changes during a session (acceptable — projects are static after discovery).
