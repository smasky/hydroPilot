### 核心证据

#### 证据 1 — cal_parmchg_read.f90（对象计数逻辑）

`cal_parmchg_read.f90` 第 108-130 行，当 calibration.cal 中 `OBJ_TOT=0`（未指定具体对象）时，按 `ob_typ` 决定 `num_elem`：

```fortran
select case (cal_parms(ipar)%ob_typ)
case ("hru")
  cal_upd(i)%num_elem = sp_ob%hru       ! HRU 总数
case ("sol")
  cal_upd(i)%num_elem = sp_ob%hru       ! HRU 总数 — 与 "hru" 相同
case ("cha")
  cal_upd(i)%num_elem = sp_ob%chan      ! Channel 总数
case ("bsn")
  cal_upd(i)%num_elem = 1               ! Basin = 1
```

**关键行**：`case ("sol")` → `cal_upd(i)%num_elem = sp_ob%hru`

当未指定对象时，`sol` 参数的默认作用范围是全部 HRU（`sp_ob%hru`），不是全部 soil profile。随后的循环 `do ie = 1, cal_upd(i)%num_elem` 将 1..N 作为对象 ID——这些是 HRU ID。

**源文件**：`swatplus-main/src/cal_parmchg_read.f90`，行 108-130
**引用行**：`case ("sol")` → `cal_upd(i)%num_elem = sp_ob%hru`

#### 证据 3 — soil_data_module.f90（数据索引方式）

土壤层的饱和导水率 `k` 的索引是 `(layer, HRU)`，不是 `(layer, soil_profile)`。这证实了 SWAT+ 内部将土壤属性按 HRU 而非按 soil profile 索引。

**源文件**：`swatplus-main/src/soil_data_module.f90`，第 49 行
